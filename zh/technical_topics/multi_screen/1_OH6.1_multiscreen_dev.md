# 多屏（Multi-Screen）二次开发指南

> 适用平台：SpacemiT K3 Pico / RISC-V，OpenHarmony 6.1（API 23）
> 适用对象：需要在应用中控制复制/扩展显示模式、调整屏幕相对摆放、跨屏拉起应用的二次开发者

---

## 1. 能力概述

多屏能力由显示管理服务（Display Manager Service）提供，对上暴露在 `@ohos.screen` 模块中。它解决的问题是：当设备接入第二块屏幕（如 K3 Pico 的 eDP + DP 双屏）后，应用如何把两块屏组织成「复制」或「扩展」的显示关系，以及如何安排它们的相对位置。

应用可用的核心能力有三项：

| 能力 | 接口 | 作用 |
|---|---|---|
| 枚举屏幕 | `screen.getAllScreens()` | 获取所有屏幕对象及其 id、尺寸、当前模式 |
| 切换显示模式 | `screen.setMultiScreenMode()` | 在复制（镜像）与扩展之间切换 |
| 调整屏幕摆放 | `screen.setMultiScreenRelativePosition()` | 指定副屏相对主屏的坐标 |

此外还有 `screen.on('change')` 用于感知屏幕状态变化。

### 1.1 一次调用经过哪些层

```
应用 (ArkTS)
    │
    ├── @ohos.screen（NAPI，SystemCapability.WindowManager.WindowManager.Core，@systemapi）
    │        interfaces/kits/napi/screen_runtime/napi/js_screen_manager.cpp
    │              ↓
    ├── libdm：ScreenManager（C++ innerkit）
    │        dm/src/screen_manager.cpp
    │              ↓
    │        dm/src/display_manager_adapter.cpp（按运行环境分发到 SceneBoard 或 DMS）
    │              ↓
    └── Display Manager Service
             dmserver/src/display_manager_service.cpp
                    ↓
             dmserver/src/abstract_screen_controller.cpp
                    ↓
             Render Service（实际合成与摆放）
```

开发者只需要关心最上层 `@ohos.screen` 的接口，下面各层是实现细节。

## 2. 使用前提

### 2.1 API 等级要求

`@ohos.screen` 属于**系统接口**（`@systemapi`），整个模块的接口都要求调用方是系统应用。这包括看起来只读的 `getAllScreens()`——它同样带 `@systemapi` 标注，非系统应用调用会直接返回 `202`。

因此二次开发的应用必须满足：

1. APL 等级不低于 `system_basic`；
2. 签名 profile 中 `app-feature` 为 `hos_system_app`；
3. 使用系统级证书签名，并以预置方式部署。

设置应用（`applications/standard/settings`）就是这样一个系统应用，其签名 profile 可作为样板：

```json
{
  "app-distribution-type": "os_integration",
  "bundle-info": {
    "bundle-name": "com.ohos.settings",
    "apl": "system_core",
    "app-feature": "hos_system_app"
  }
}
```

需要注意，这些接口**不需要**在 `module.json5` 的 `requestPermissions` 中声明运行时权限——门槛是 APL 等级而非权限列表。这与 `ACCESS_VIRTUAL_SCREEN` 那类带 `@permission` 标注的接口不同。

### 2.2 非系统接口的替代方案

如果应用无法获得系统身份，`@ohos.display` 中的以下接口是公开的（`@atomicservice`，无 `202` 限制），可用于**感知**多屏，但不能主动切换模式：

| 接口 | 用途 |
|---|---|
| `display.getAllDisplays()` | 枚举所有显示设备 |
| `display.getDefaultDisplaySync()` | 获取默认（主）显示设备 |

配合 `startAbility({ displayId })` 可以把应用拉起到指定屏幕，这条路径同样不需要系统身份。

## 3. API 参考

### 3.1 枚举屏幕

```typescript
function getAllScreens(): Promise<Array<Screen>>;
function getAllScreens(callback: AsyncCallback<Array<Screen>>): void;
```

| 项 | 值 |
|---|---|
| 模块 | `@ohos.screen` |
| SysCap | `SystemCapability.WindowManager.WindowManager.Core` |
| 权限等级 | `@systemapi` |
| 起始版本 | 动态 `@since 9`，静态 `@since 23` |

**返回值**：`Screen` 对象数组。

**异常码**：`202`（非系统应用）、`1400001`（显示或屏幕无效）。

### 3.2 Screen 对象

```typescript
interface Screen {
  readonly id: long;                          // 屏幕 id，多屏接口使用这个值
  readonly rsId: long;                        // RenderService 侧 id
  readonly name: string;
  readonly parent: long;
  readonly activeModeIndex: long;             // 当前模式的数组下标
  readonly supportedModeInfo: Array<ScreenModeInfo>;
  readonly orientation: Orientation;
  readonly sourceMode: ScreenSourceMode;
  readonly serialNumber?: string;

  setOrientation(orientation: Orientation): Promise<void>;
  setScreenActiveMode(modeIndex: long): Promise<void>;
}

interface ScreenModeInfo {
  readonly id: long;
  readonly width: long;
  readonly height: long;
  readonly refreshRate: long;
}
```

**常用字段说明**

| 字段 | 说明 |
|---|---|
| `id` | 调用 `setMultiScreenMode` / `setMultiScreenRelativePosition` 时传入的正是这个值 |
| `rsId` | 渲染服务侧编号，一般无需直接使用 |
| `activeModeIndex` | 当前生效模式在 `supportedModeInfo` 数组中的下标，**可直接用作数组索引** |
| `supportedModeInfo` | 该屏支持的所有分辨率模式，按服务端顺序排列 |
| `sourceMode` | 该屏当前在显示关系中的角色，取值见下表 |

**`ScreenSourceMode` 取值**

| 值 | 名称 | 含义 |
|---|---|---|
| 0 | `SCREEN_MAIN` | 主屏 |
| 1 | `SCREEN_MIRROR` | 镜像（复制模式下的副屏） |
| 2 | `SCREEN_EXTEND` | 扩展（扩展模式下的副屏） |
| 3 | `SCREEN_ALONE` | 独立 |

判断当前是复制还是扩展，最可靠的方式是看副屏的 `sourceMode`：为 `SCREEN_MIRROR` 即复制模式，为 `SCREEN_EXTEND` 即扩展模式。不要自行缓存模式状态，切换失败或外部修改时会出现不一致。

**取当前分辨率的写法**

```typescript
const modes = screen.supportedModeInfo;
const idx = screen.activeModeIndex;
const width = (modes && idx >= 0 && idx < modes.length) ? modes[idx].width : 0;
const height = (modes && idx >= 0 && idx < modes.length) ? modes[idx].height : 0;
```

> 注意：`activeModeIndex` 是数组下标，而 `supportedModeInfo[i].id` 是该模式自身的编号，两者语义不同，不能互相比较。

### 3.3 切换显示模式

```typescript
function setMultiScreenMode(
  primaryScreenId: long,
  secondaryScreenId: long,
  secondaryScreenMode: MultiScreenMode
): Promise<void>;
```

| 项 | 值 |
|---|---|
| 权限等级 | `@systemapi` |
| 起始版本 | 动态 `@since 13`，静态 `@since 23` |
| 返回值 | `Promise<void>` |

**参数**

| 参数 | 类型 | 说明 |
|---|---|---|
| `primaryScreenId` | `long` | 主屏的 `Screen.id`。复制模式下它是被镜像的源屏；扩展模式下它占据坐标系原点 |
| `secondaryScreenId` | `long` | 副屏的 `Screen.id`，不能与主屏相同 |
| `secondaryScreenMode` | `MultiScreenMode` | 目标模式 |

**`MultiScreenMode` 枚举**

```typescript
enum MultiScreenMode {
  SCREEN_MIRROR = 0,   // 复制
  SCREEN_EXTEND = 1    // 扩展
}
```

**行为说明**

- 切到复制模式时，副屏内容与主屏完全一致。
- 切到扩展模式时，系统会给出一个默认布局：主屏在原点，副屏紧贴主屏右边缘，副屏起点为 `(主屏宽度, 0)`。若需要其他方位，随后再调用 `setMultiScreenRelativePosition()`。

**异常码**

| 错误码 | 含义 |
|---|---|
| `202` | 非系统应用调用 |
| `401` | 参数错误（缺参、类型错误、屏 id 非法） |
| `1400003` | 显示管理服务异常 |

两个屏 id 相同、或任一为 `SCREEN_ID_INVALID` 时返回 `401`。

### 3.4 调整屏幕摆放

```typescript
function setMultiScreenRelativePosition(
  mainScreenOptions: MultiScreenPositionOptions,
  secondaryScreenOptions: MultiScreenPositionOptions
): Promise<void>;
```

| 项 | 值 |
|---|---|
| 权限等级 | `@systemapi` |
| 起始版本 | 动态 `@since 13`，静态 `@since 23` |

**参数结构**

```typescript
interface MultiScreenPositionOptions {
  id: long;      // 屏幕的 Screen.id
  startX: long;  // 屏幕原点 X 坐标
  startY: long;  // 屏幕原点 Y 坐标
}
```

**坐标规则（务必先读）**

1. 坐标单位是**物理像素**，全局只有一个 display group 坐标系。
2. **主屏固定在 `(0, 0)`**，传入非零值会被服务端忽略（仅打一条警告日志）。也就是说这个接口**实际只能移动副屏**。
3. 两侧坐标必须都传全，即使主屏那两个值不会被采用。
4. 坐标取值范围为 `0 ~ 100000`，超限返回 `401`。
5. 传入的屏必须是物理屏。屏幕组和虚拟屏不能摆放，会直接失败。
6. **副屏无法摆到主屏左侧**：`startX` / `startY` 在底层是 `uint32_t`，表达不了负坐标；同时系统主屏永远锁定在原点，对调两块屏的角色也无法绕开。若物理摆放确实是副屏在左，建议在界面层用「主屏在右」的视觉隐喻呈现，系统坐标系里依旧是主屏在原点、副屏在其右侧。

**两种常用摆放**

```typescript
// 副屏在主屏右侧
const main    = { id: primaryId,   startX: 0,            startY: 0 };
const right   = { id: secondaryId, startX: primaryWidth, startY: 0 };
await screen.setMultiScreenRelativePosition(main, right);

// 副屏在主屏下方
const bottom  = { id: secondaryId, startX: 0, startY: primaryHeight };
await screen.setMultiScreenRelativePosition(main, bottom);
```

**异常码**：`202`、`401`、`1400001`（显示或屏幕无效）、`1400003`。

### 3.5 监听屏幕变化

```typescript
function on(eventType: 'connect' | 'disconnect' | 'change', callback: Callback<long>): void;
function off(eventType: 'connect' | 'disconnect' | 'change', callback?: Callback<long>): void;
```

| 事件 | 触发时机 |
|---|---|
| `connect` | 有新屏幕接入 |
| `disconnect` | 屏幕被移除 |
| `change` | 屏幕属性变化（模式切换、分辨率变更、方位调整等） |

**两个实践要点**

1. **必须保存回调引用**，否则 `off()` 无法移除，每次进入页面都会泄漏一个监听。
2. 切换显示模式时，合成器会在一段时间内连续发出多个 `change` 事件，应做去抖合并（设置应用使用 500ms）。

### 3.6 相关接口：在指定屏幕拉起应用

```typescript
// @ohos.app.ability.StartOptions
interface StartOptions {
  displayId?: long;   // 目标显示设备 id
  windowMode?: AbilityConstant.WindowMode;
}
```

| 项 | 说明 |
|---|---|
| 所属模块 | `@ohos.app.ability.StartOptions` |
| 权限等级 | 公开接口，无需系统身份 |
| id 来源 | `@ohos.display` 的 `Display.id`，**不是** `Screen.id` |

```typescript
await context.startAbility(
  { bundleName: 'com.example.app', abilityName: 'EntryAbility' },
  { displayId: displayId }
);
```

`windowMode: AbilityConstant.WindowMode.WINDOW_MODE_FLOATING` 可以以浮动窗口方式拉起，仅在扩展模式下有意义。

## 4. 两套 id 的区别

同一块物理屏在系统中存在两套编号，公开接口不提供二者的映射关系：

| id | 来源 | 谁使用它 |
|---|---|---|
| `Screen.id` | `@ohos.screen` 的 `Screen.id` | `setMultiScreenMode`、`setMultiScreenRelativePosition`、`setOrientation` |
| `Display.id` | `@ohos.display` 的 `Display.id` | `startAbility({ displayId })`、`display.getScreenshots()` |

两者数值不同（实测 `Screen.id` 为 0/2 时，对应 `Display.id` 为 10/16，且无固定偏移），并且 **`Display.id` 在每次切换显示模式时都会重新分配**，而 `Screen.id` 相对稳定。

因此应用侧需要自行维护映射。设置应用中采用的处理方式可以直接借鉴：

1. **主屏**：取 `display.getDefaultDisplaySync().id`，并要求该 display 的物理尺寸与 `Screen` 当前分辨率一致；
2. **副屏**：跳过默认 display，只接受尺寸唯一匹配的结果；若两块屏分辨率相同导致匹配不唯一，宁可返回「未匹配」也不猜测；
3. **复制模式**：系统只暴露一个 display，副屏匹配不到属于正常现象，此时沿用该唯一 display 即可；
4. **匹配失败**：把 `displayId` 置为 `-1` 并提示用户，**不要用 `Screen.id` 冒充 `Display.id` 去拉起应用**。

## 5. Demo：模式切换与屏幕摆放

下面这段示例覆盖了常用接口，可直接放入系统应用运行。

```typescript
// MultiScreenDemo.ets
import screen from '@ohos.screen';

const MODE_MIRROR = 0;
const MODE_EXTEND = 1;

interface ScreenPair {
  primary: screen.Screen;
  secondary: screen.Screen;
  primaryWidth: number;
  primaryHeight: number;
}

@Entry
@Component
struct MultiScreenDemo {
  @State screens: screen.Screen[] = [];
  @State currentMode: number = MODE_EXTEND;
  @State message: string = '';
  private changeCallback: ((id: number) => void) | null = null;
  private debounceTimer: number = -1;

  aboutToAppear(): void {
    this.refresh();
    this.registerObserver();
  }

  aboutToDisappear(): void {
    this.unregisterObserver();
  }

  /** 读取所有屏幕，并从副屏的 sourceMode 反推当前模式 */
  private async refresh(): Promise<void> {
    try {
      this.screens = await screen.getAllScreens();
      const pair = this.pickPair();
      if (pair !== null && pair.secondary.sourceMode === screen.ScreenSourceMode.SCREEN_MIRROR) {
        this.currentMode = MODE_MIRROR;
      } else {
        this.currentMode = MODE_EXTEND;
      }
      this.message = `共 ${this.screens.length} 块屏`;
    } catch (err) {
      this.message = `枚举屏幕失败: ${err.code}, ${err.message}`;
    }
  }

  /** 取屏幕当前分辨率 */
  private getSize(s: screen.Screen): { w: number, h: number } {
    const modes = s.supportedModeInfo;
    const idx = s.activeModeIndex;
    if (!modes || idx < 0 || idx >= modes.length) {
      return { w: 0, h: 0 };
    }
    return { w: modes[idx].width, h: modes[idx].height };
  }

  /** 按 sourceMode 挑出主屏，其余任取一块作副屏 */
  private pickPair(): ScreenPair | null {
    if (this.screens.length < 2) {
      return null;
    }
    let primary: screen.Screen = this.screens[0];
    for (const s of this.screens) {
      if (s.sourceMode === screen.ScreenSourceMode.SCREEN_MAIN) {
        primary = s;
        break;
      }
      if (s.id < primary.id) {
        primary = s;
      }
    }
    let secondary: screen.Screen | null = null;
    for (const s of this.screens) {
      if (s.id !== primary.id) {
        secondary = s;
        break;
      }
    }
    if (secondary === null) {
      return null;
    }
    const { w, h } = this.getSize(primary);
    return { primary: primary, secondary: secondary, primaryWidth: w, primaryHeight: h };
  }

  /** 切换复制 / 扩展 */
  private async setMode(mode: number): Promise<void> {
    const pair = this.pickPair();
    if (pair === null) {
      this.message = '需要连接两块屏幕';
      return;
    }
    if (mode === this.currentMode) {
      return;
    }
    try {
      await screen.setMultiScreenMode(pair.primary.id, pair.secondary.id, mode);
      this.currentMode = mode;
      this.message = mode === MODE_EXTEND ? '已切换到扩展模式' : '已切换到复制模式';
    } catch (err) {
      this.message = `切换失败: ${err.code}, ${err.message}`;
      await this.refresh();   // 失败后重读真实状态，避免界面与系统不一致
    }
  }

  /** 摆放副屏：toBottom 为 false 表示放右侧，true 表示放下方 */
  private async arrange(toBottom: boolean): Promise<void> {
    const pair = this.pickPair();
    if (pair === null) {
      this.message = '需要连接两块屏幕';
      return;
    }
    if (this.currentMode !== MODE_EXTEND) {
      this.message = '只有扩展模式才能调整方位';
      return;
    }
    const main = { id: pair.primary.id, startX: 0, startY: 0 };
    const secondary = toBottom
      ? { id: pair.secondary.id, startX: 0, startY: pair.primaryHeight }
      : { id: pair.secondary.id, startX: pair.primaryWidth, startY: 0 };
    try {
      await screen.setMultiScreenRelativePosition(main, secondary);
      this.message = toBottom ? '副屏已移到下方' : '副屏已移到右侧';
    } catch (err) {
      this.message = `调整方位失败: ${err.code}, ${err.message}`;
    }
  }

  private registerObserver(): void {
    this.changeCallback = (id: number) => {
      if (this.debounceTimer >= 0) {
        clearTimeout(this.debounceTimer);
      }
      this.debounceTimer = setTimeout(() => {
        this.debounceTimer = -1;
        this.refresh();
      }, 500);
    };
    screen.on('change', this.changeCallback);
  }

  private unregisterObserver(): void {
    if (this.changeCallback !== null) {
      screen.off('change', this.changeCallback);
      this.changeCallback = null;
    }
    if (this.debounceTimer >= 0) {
      clearTimeout(this.debounceTimer);
      this.debounceTimer = -1;
    }
  }

  build() {
    Column({ space: 12 }) {
      Text('多屏控制').fontSize(20).fontWeight(FontWeight.Bold)

      Text(`屏幕数：${this.screens.length}`).fontSize(14)
      ForEach(this.screens, (s: screen.Screen) => {
        Text(`id=${s.id} ${this.getSize(s).w}x${this.getSize(s).h} sourceMode=${s.sourceMode}`)
          .fontSize(12)
      }, (s: screen.Screen) => `screen_${s.id}`)

      Row({ space: 8 }) {
        Button('扩展模式').onClick(() => { this.setMode(MODE_EXTEND); })
        Button('复制模式').onClick(() => { this.setMode(MODE_MIRROR); })
      }

      Row({ space: 8 }) {
        Button('副屏放右侧').onClick(() => { this.arrange(false); })
        Button('副屏放下方').onClick(() => { this.arrange(true); })
      }

      Text(this.message).fontSize(14).fontColor('#007DFF')
    }
    .width('100%')
    .padding(16)
    .alignItems(HorizontalAlign.Start)
  }
}
```

### 5.1 示例中的几处设计考虑

- **模式从 `sourceMode` 反推**而不是自行保存状态位，切换失败或外部改变时界面不会出错。
- **切换前判断模式是否相同**，相同则跳过，避免重复下发导致合成器抖动。
- **失败后调用 `refresh()`** 重新读取真实状态。
- **方位调整前校验是否处于扩展模式**，复制模式下调整方位没有意义。
- **主屏判定以 `SCREEN_MAIN` 为准**，不假设 id 最小者就是主屏。

## 6. 故障排查

### 6.1 错误码

| 错误码 | 含义 | 处理方式 |
|---|---|---|
| `202` | 非系统应用调用系统接口 | 按第 2 章提升 APL 等级并重新签名；申请权限无效 |
| `401` | 参数错误 | 检查参数完整性、类型，以及坐标是否超出 `0 ~ 100000`；确认传入的是 `Screen.id` |
| `801` | 设备不支持 | 确认设备的显示管理能力已启用 |
| `1400001` | 显示或屏幕无效 | 重新调用 `getAllScreens()`；模式切换后 id 可能变化 |
| `1400003` | 显示管理服务异常 | 抓取窗口子系统日志进一步定位 |

### 6.2 常见现象

**应用被拉起到错误的屏幕** —— 通常是把 `Screen.id` 当成 `Display.id` 用了。参照第 4 章的配对方式处理。

**切换模式后提示 display 不存在** —— `Display.id` 在模式切换时会重新分配。不要缓存，每次使用前重新枚举。

**调用摆放接口成功但主屏没动** —— 这是正常行为，主屏固定在原点，只移动副屏。

**副屏左侧摆放失败** —— 接口不接受负坐标，详见 3.4 第 6 条。

**切换模式时屏幕短暂闪烁** —— 合成器在重建显示关系，属于预期现象。

**监听回调触发过于频繁** —— 模式切换会连续产生多个 `change` 事件，需要做去抖处理。
