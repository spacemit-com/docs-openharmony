### 4.2. 北向开发（应用）

使用 DevEco Studio 6.1 开发 RISC-V 应用时，需要先让 IDE 的 NDK 支持 `riscv64`。DevEco Studio 6.1 默认只提供 `arm64-v8a` / `armeabi-v7a` / `x86_64` 三个 ABI，需要修改 hvigor 插件才能选择 `riscv64`。

不同 6.1.x 小版本的插件内容略有差异，补丁可能需要按实际版本微调。

#### 4.2.1 定位 hvigor 插件目录

hvigor-ohos-plugin 位于 DevEco Studio 安装目录下，常见路径：

```bash
<DevEco Studio>/tools/hvigor/hvigor-ohos-plugin
```

> 若使用命令行构建（`hvigorw`），插件也可能位于工程或全局的 `~/.hvigor` 缓存目录下，按实际使用的插件为准。

#### 4.2.2 需要修改的文件

补丁涉及 11 个文件，分两类：

**（1）构建配置 schema（8 个 JSON）**：在 ABI 枚举中追加 `riscv64`

**（2）ABI 枚举与清理逻辑（3 个 JS/TS）**：增加 `riscv64` 到 `riscv64-linux-ohos` 的映射，并让 `clean` 任务能识别 `riscv64` 目录

具体修改内容见下载的补丁文件。

**[📥 下载完整补丁：oh61-deveco-riscv64.diff](../oh61-deveco-riscv64.diff)**

#### 4.2.3 应用补丁

在 hvigor 插件目录的上一级执行：

```bash
cd <DevEco Studio>/tools/hvigor
patch -p1 < oh61-deveco-riscv64.diff
```

补丁文件与工程一起维护（`oh61-deveco-riscv64.diff`），可直接用 `git apply` 或 `patch -p1` 应用。若某个小版本报上下文不匹配，按 4.2.2 的三处改动手工补齐即可。

#### 4.2.4 使用

修改完成后，重新打开工程，在 `build-profile.json5` 中即可选择 `riscv64`：

```json5
{
  "app": {
    "products": [
      {
        "name": "default",
        "externalNativeOptions": {
          "path": "./src/main/cpp/CMakeLists.txt",
          "arguments": "",
          "cppFlags": "",
          "abiFilters": ["riscv64"]
        }
      }
    ]
  }
}
```

编译出的 native 库会输出到 `.cxx/riscv64` 与 `libs/riscv64` 目录。

> 注意：`clean.js` 的改动只影响 `clean` 任务能否删除 `riscv64` 产物目录，不影响编译本身；若未修改 `clean.js`，清理时可能残留旧产物。
